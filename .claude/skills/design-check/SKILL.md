# 디자인 점검

화면을 고친 뒤 "됐다"고 말하기 전에, 사람이 눈으로 찾을 법한 문제를 먼저 직접 찾는다. 숫자로 재는 검사는 놓치는 것(색, 여백 느낌)이 있어서 스크린샷 확인과 같이 쓴다.

## 순서

1. `mkdocs build --strict`로 `site/`를 만든다. **`-q`는 붙이지 않고 종료 코드(`echo $?`)가 0인지 확인한다.** `-q`는 경고가 있어도 0으로 끝나 깨진 링크를 숨긴다.
2. 서버로 띄운다. 파일(file://)로 열면 검색창 같은 스크립트 의존 요소가 숨겨져 틀린 결과가 나온다.
   `python3 -m http.server 8765 --directory site &`
3. 점검한다. 홈과 새로 쓴 페이지를 넣는다.
   `node .claude/skills/design-check/scripts/check_layout.js http://localhost:8765 / /part1/ch01/next-word/ --out=<스크린샷 폴더>`
4. 결과의 "문제 없음"과 별개로 스크린샷을 최소 모바일(360)과 데스크톱(1280) 하나씩 눈으로 본다.
5. 문제가 나오면 원인을 먼저 찾는다. 사이트 문제인지, 미리보기 변환 문제인지 구분한다.
   미리보기는 `<html>`의 `dir="ltr"` 같은 속성과 스크립트가 빠지면 Material 규칙이 깨진다.

## 검사 항목

가로 스크롤, 헤더·사이드바·본문 영역 겹침, 헤더 안 요소 겹침, 잘리는 글자, 왼쪽 메뉴의 같은 문장 반복. 5개 화면 폭(360, 768, 1000, 1280, 1600)에서 돌린다.

## 한계

색 대비, 서체 느낌, 어두운 모드는 자동으로 보지 못한다. 필요하면 `.md-header` 팔레트 토글을 눌러 스크린샷을 따로 찍는다.
